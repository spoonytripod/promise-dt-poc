# 자산 관리 실행 안내와 검증 결과

검증일: 2026-10-02. Windows에 설치된 Chrome과 Edge를 Playwright로 실행하여 확인했습니다. 검사 화면은 1920×1080 기준입니다. 시제품 구현 범위는 AM-01부터 AM-18까지입니다.

## 실행

Web 화면:

```powershell
python -m http.server 8000
```

브라우저에서 http://localhost:8000/pages/page-asset.html 을 여십시오. 최초 실행에만 예시 데이터를 생성합니다. 다른 주소와 포트를 사용하면 브라우저 저장소도 달라집니다.

단일 HTML:

```powershell
python scripts/create_standalone.py
```

루트의 demo_standalone.html을 Chrome 또는 Edge로 여십시오. 기존 로그인 예시 화면을 지나 상단의 설계 정보 및 자산 관리 메뉴로 이동합니다. 자산 화면에 필요한 업무 코드, 저장 서비스, 스타일, SheetJS와 예시 문서는 내장됩니다. 생성물을 직접 수정하지 않습니다.

데이터와 첨부파일은 해당 브라우저의 IndexedDB에 저장됩니다. Web과 단일 HTML의 데이터는 독립적입니다. 브라우저 데이터를 삭제하거나 시크릿 모드를 종료하면 보관 내용이 사라질 수 있습니다. 파일 이름이나 위치를 바꾼 경우 로컬 파일 저장소의 동일성은 브라우저 정책에 따라 달라질 수 있으므로 검증된 동일 경로에서 실행하십시오.

## 재검증

Node.js 20 이상과 Python을 사용합니다. package.json의 의존성은 검증용이며 화면 실행에는 설치가 필요하지 않습니다. Chrome과 Edge 실행 파일은 스크립트에 표준 Windows 설치 경로로 지정되어 있습니다.

```powershell
npm ci
npm test
python scripts/create_standalone.py
```

별도 터미널에서 python -m http.server 8000 을 실행한 상태로 아래 검사를 수행합니다.

```powershell
npm run test:storage
npm run test:browser
```

저장 검사는 임시 프로필과 일시적인 probe HTML을 사용하며 실행 후 probe HTML을 제거합니다. 브라우저 검사는 실제 사용자 브라우저 프로필 대신 임시 프로필을 사용합니다. 검증 산출물은 docs/asset-validation에 다시 생성됩니다.

## 확인된 제약과 후속 작업

- 실제 PostgreSQL 스키마 변경, 인증과 권한 구분, SCADA 및 실제 3D 객체 연결은 이번 범위 밖입니다. 원격 배포는 수행하지 않았습니다.
- 생성기가 과거 concept.glb 경로를 사용하고 있어 현재 메인 화면의 models/seperated_comp.glb를 내장하지 못하는 문제를 수정했습니다. 현재 모델은 번들에 포함됩니다. 메인 3D 화면의 기존 외부 라이브러리 의존성은 유지하므로, 자산 화면 외의 전체 사이트가 오프라인으로 완전히 동작한다고 검증한 결과는 아닙니다.
- 설치 이력은 날짜 단위입니다. 동일 일자의 교체 전후 수행 시각까지 구분하려면 실제 서비스에서 timestamp 정책을 정해야 합니다.
- 엑셀은 자산대장 시트를 사용합니다. 날짜는 YYYY-MM-DD, 신규 설치 자산의 상태는 가동 또는 정지, 태그가 없는 자산은 예비입니다. 폐기 자산은 신규 등록 후 폐기 기능에서 일자와 사유를 입력합니다. 기존 자산 일괄 수정은 지원하지 않습니다. 파일은 20 MB, 한 번의 검토는 10,000행 이하입니다.
- 실제 DB 전환에는 불변 키와 자산번호의 분리 정책, 설치 및 수행 이력, 파일 원본과 연결, 변경 이력의 테이블 확장이 필요합니다. 자세한 대응은 [구현 명세](ASSET_MANAGEMENT_SPEC.md)에 있습니다.
- 저장 응답이 시간 초과된 경우 성공으로 표시하지 않습니다. 저장 데이터 새로고침으로 실제 상태를 확인한 후 다시 처리하십시오.
- 회귀 검증은 공통 메뉴와 자산 및 진단 페이지 왕복을 확인했습니다. 다른 메뉴의 모의 분석이나 예측 기능을 실제 구현으로 검증한 결과는 아닙니다.

단일 HTML 검증에서 발견한 공통 스크립트 주석의 닫는 script 문자열, 라이브러리 내부 head 문자열의 전역 치환과 변수 기반 메뉴 이동을 생성기에서 수정했습니다. 메인 안내창의 localStorage 접근도 로컬 Blob iframe에서 오류가 발생하지 않도록 보호했습니다. 자산 저장은 계속 부모 래퍼의 IndexedDB를 사용합니다.

## 기준정보 처리 열 표시 개선

설비 분류, 제조사, 관리 기관과 태그 계층 테이블에서 처리 열을 첫 번째로 배치했습니다. 수정은 연필 아이콘, 삭제 또는 비활성화는 휴지통 아이콘으로 표시합니다. 각 버튼의 title과 접근성 이름에 기능을 유지합니다. 태그 계층은 기존과 같이 수정 기능만 제공합니다.

Chrome과 Edge에서 Web 및 단일 HTML의 네 테이블 열 순서, 아이콘 접근성 이름, 수정 창 열기와 삭제 확인 창을 검증하여 4가지 실행 조합 모두 통과했습니다. [검증 결과](css-validation/master-actions-results.json)와 [변경 화면](css-validation/Chrome-master-actions-web.png)을 보관했습니다.
